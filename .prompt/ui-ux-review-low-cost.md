# UI/UX レビュー（低コスト & 実用指向）

以下の手順で画面の挙動とデザインを確認し、実用的かつモダンなWeb標準に基づいたUI/UXレビューを行ってください。

## 確認対象

- URL: `http://localhost:3000/editor`
- 確認シナリオ:
  1. 初期画面の表示（ツールバー、キャンバス、各種ガイド）
  2. 「大問を作成・追加」ボタン押下後のモーダル（入力項目、パターン選択、操作導線）
  3. （必要に応じて）「用紙に配置する」後のキャンバス状態・プロパティパネル

## 使用する MCP

- **使用する**: Cursor 組み込みの `cursor-ide-browser`（`browser_*` ツール）
- **使用しない**: `chrome-devtools-mcp`（技術調査が明示的に必要な場合のみ）

## トークン削減ルール（必須・厳守）

1. **挙動確認は `browser_snapshot` を最優先**
   - `compact: true` を基本とする
   - 操作可能要素のみ確認時は `interactive: true`
   - 特定領域のみ確認時は `selector` でスコープを絞る
   - 状態変化の確認は `includeDiff: true` で差分のみ取得
2. **スクリーンショットは必要最小限（最大 3 枚まで）**
   - 初期画面: 1 枚（全体レイアウト・配色の把握）
   - モーダル表示時: 1 枚（モーダルの視認性・入力要素の配置把握）
   - 配置後キャンバス: 1 枚（必要時のみ）
   - レイアウトや余白の微調整確認が不要な場合は 0〜1 枚で済ませる
3. **`browser_take_screenshot` の連発禁止**
   - 1クリックごとに撮影しない
   - `take_screenshot_afterwards` は使用しない
4. **不要なツールの実行禁止**
   - Lighthouse、Performance trace、Heap snapshot、Network 一覧等は使用しない
   - `browser_cdp` は重大なエラー調査時のみ
5. **重複取得の回避**
   - 直前の snapshot / screenshot で判断可能な場合は再取得しない

## レビュー観点（3つの柱）

### 1. UX（操作性・導線）

- **初見での迷い**: 初めて使う教員・ユーザーが「次に何をすべきか」直感的に理解できるか
- **視線移動・アクションの無駄**: ツールバー、キャンバス、モーダル間で行ったり来たりする視線・マウスクリックに無駄がないか
- **状態フィードバック**: 選択中・未選択（disabled）・ローディング・配置完了などの状態が明確に伝わっているか

### 2. UI（視認性・配置）

- **情報の優先順位（ビジュアルヒエラルキー）**:
  - ボタンの強弱（Primary / Secondary / Ghost / Danger）が正しく機能しているか（保存系と作成系のどちらが目立つべきか等）
  - 余白（Padding / Margin）のリズム、フォントサイズ・ウェイトの階層構造が整理されているか
- **視認性と整理度**:
  - ガイドライン（余白・折り目・配置）が作業の邪魔になっていないか
  - 設定スライダーやチェックボックスのグループ化が適切か

### 3. 解答用紙作成アプリ特有の課題

- **フォーム・キャンバス作成ツールとしての直感性**:
  - 大問番号・配点・小問パターンの入力ステップが作業フローに沿っているか
  - 用紙（B4横 左右2分割）の構造や印刷前提の余白感が画面上で掴みやすいか
  - 大問の追加・移動・プロパティ変更の行き来がスムーズか

## デザイン方針・注意事項（必須遵守）

- **過剰な装飾の排除**:
  - グラデーション、派手なシャドウ、過剰なアニメーションなど、いわゆる「AIが生成したような過度な装飾」の提案は一切不要です。
- **実用的でモダンなWeb標準の準拠**:
  - Google Material Design や Tailwind UI のような、**シンプル・クリーン・実用的** な業務Webアプリケーションの標準に合わせた提案を行ってください。
  - 一貫性のあるスペーシング体系（4px/8pxグリッド等）、意味のあるカラーパレット（状態色・アクセント色の統一）、アクセシビリティ（十分なコントラスト比・明確なフォーカスリング）を重視してください。
